# Internationalisation (i18n)

PetPattern ships its UI in **8 languages**: English (base), Croatian, German,
Spanish, French, Italian, Norwegian (Bokmål), Polish. Users pick from a flag
dropdown in the header; the choice persists in `localStorage`.

## How it works (frontend)

- English strings are their **own keys** and the default. Any key not translated
  for a locale falls back to English — never a missing key, never a broken screen.
- Each locale is one file: `frontend/src/locales/<code>.js`, exporting
  `{ "<English key>": "<translation>", ... }`. Every locale has the same 411 keys.
- `frontend/src/i18n.js` wires them up: `LANGUAGES` (code + native label),
  `LOCALES` (the maps), and `t(key, vars)` which interpolates `{placeholders}`.
- `LangToggle` (in `App.jsx`) renders the flag dropdown; flags are inline SVG
  (`Flag` component) so they render identically on every OS — emoji flags show as
  bare letters on Windows.

### Adding or editing a language

1. Copy an existing `locales/*.js`, translate the values (keep keys and every
   `{placeholder}` exactly).
2. Add `{ code, label }` to `LANGUAGES` in `i18n.js` and import the map into
   `LOCALES`.
3. Add a flag case to `Flag` in `App.jsx`.

Keys must stay identical across locales — the app assumes English keys everywhere.

## Backend content

Backend-generated text — pattern cards, the "What changed?" timeline, vet
summary, recap, and the AI note reminder — is localised **server-side** in
`backend/.../i18n/Copy.java`, selected from the request's `Accept-Language`
(`api.js` sends the current UI language). **All 8 languages are covered:**

- Croatian stays inline in `Copy.java` (the `HR` map).
- The six new locales load from `backend/src/main/resources/i18n/<code>.json`
  (English key → translation, 230 keys each). Adding a language = adding a JSON
  file; `Copy.loadExtra()` reads them at startup, missing keys fall back to
  English.
- Grammar helpers are per-language: `days()`/`years()` pluralisation,
  `protein()` names (e.g. `Huhn` / `pollo` / `poulet` / `kylling` / `kurczak`),
  and `locale()` for date formatting.

The 230 backend strings were machine-translated and then **independently
double-checked by a second native pass** per language (medical safety,
placeholder integrity, natural phrasing). Verified live end-to-end across all six
locales.

### Known limitation → native review still recommended before market launch

The vet summary assembles some **sentence fragments** ("… on {0} days", clause
lists) whose grammar can't always be perfect from a fixed template — e.g. German
dative reads "an 9 Tage" where "an 9 Tagen" would be ideal. It's clear and
non-diagnostic, but a native (ideally vet-aware) pass to polish these fragments —
and to sign off the medical-safe framing per market — is recommended before a
public launch in each language.

## Notes

- Bundle: eager-loading all locales adds ~160 KB (~120 KB gzipped). If that
  matters later, lazy-load the non-active locale via dynamic `import()`.
- Legal pages (`legal.js`) and the reset-password email are separate surfaces;
  they currently follow the English/HR split and are a candidate for the same
  locale treatment.
